# Z3 native source evidence

The existing `IGitService` gains the read-only `getSourceSnapshot({ workspacePath })` method returning shared `GitSourceSnapshot`: `baseline`, `scope`, `files`, `complete`, and `issues`. Each file contains workspace-relative `path`, `status`, optional `beforeText`, `afterText`, native `diff`, and `issue`. Graph adapts this DTO without another source owner. Its evidence port computes SHA-256 over the supplied canonical string and never adds capture timestamps.

The native service uses its existing Git command provider, repository resolver, and the injected existing `IFileService` for bounded working-tree reads. Host composition supplies the same file service used elsewhere. No provider configuration, agent input, Git index, reference, commit, checkpoint, credential, or project file is written. Missing file-service support is incomplete evidence, never simulated content.

Coverage is Git-tracked changes and non-ignored untracked paths beneath the captured workspace. Ignored files and unchanged file contents are excluded. A workspace may be a repository subdirectory. Git porcelain-v2 status is scoped to that directory, requests all untracked files, disables rename detection, and includes submodule changes. Consequently renames appear as deletion/addition. Files have `staged:<XY-index-character>`, `unstaged:<XY-worktree-character>`, or `untracked` status; a path with staged and unstaged changes appears twice. Empty untracked files remain visible. The before/after pair is HEAD/index for staged entries and index/worktree for unstaged entries. Untracked entries have an empty before-text. Diff is the existing native Git patch with external diff and text conversion disabled; untracked text is represented directly by its before/after pair.

Fixed limits are 64 changed/untracked paths, 128 KiB per blob or working-tree text, 256 KiB per diff, 1 MiB total retained before/after/diff bytes, and 512 KiB each for status and scoped index enumeration. Existing Git command time limits apply. Limits are explicit incomplete results with visible diagnostics; there is no collapsed-directory fallback and no silent omission. Binary/NUL or invalid UTF-8 text, unreadable files, conflicts, nonregular files, symbolic links, submodules, sparse/assume-unchanged index entries, unsafe paths, and unsupported records are incomplete. Working-tree paths and their ancestors are checked without following symbolic links before a bounded native read.

`baseline` is stable JSON with format version, exact HEAD object ID (or `unborn`), and SHA-256 of the scoped index and status manifests. It includes index stage/mode/blob identity even for unchanged tracked paths. Snapshot paths are sorted deterministically and contain no capture time. To reject a mixed snapshot when files change during capture, the service performs two bounded independent reads and compares their complete serialized results; a difference returns incomplete evidence. This detects changes observed across those reads, not arbitrary writes after capture. Graph's decision/continuation/pre-dispatch rechecks are still required. Neither hashing nor the metadata ownership lock locks project files.

Independent synthetic Git fixtures verify literal tracked, staged/unstaged, untracked and empty-file content; stable snapshots; changed text/HEAD/index fingerprints; workspace scoping; ignored-file exclusion; binary/oversize/path-count failures; read failures and capture races; unsupported index modes; and absence of index/reference writes. Fixtures isolate Git configuration and disable hooks/signing. User repositories, installed configuration and credentials are not used.
