## 2. What was implemented (product code)

- **Pre-reconciliation snapshot.** `GraphState.load` preserves the exact bytes it read from disk before the first change to an existing record, inside the existing serialized flight and while the Host holds the record's ownership lock. Content-addressed (`reconcile-snapshots/<workspace hash>/<sha256 of bytes>.json`), deduplicated, written with temp file + fsync + atomic rename. The repository re-reads the file and requires its hash to equal what was read; a mismatch, a missing file or a failed write aborts the load before any mutation. Ordinary saves never snapshot. No database, no migration framework.
- **Retention.** At most 20 snapshots per workspace; the oldest by modification time are removed after a successful snapshot, never the one just saved or an `alsoKeep` one, and only `<64 hex>.json` regular files in that workspace's snapshot folder. No retention UI.
- **Unsupported newer data.** `read` detects an integer version above 5 at the top level, in `definition.version` or in `runs[].version` and throws `GraphRecordUnsupportedVersionError`: a bounded readable message pointing to [GRAPH_DATA_OPERATIONS.md](GRAPH_DATA_OPERATIONS.md), the location and version, and the authoritative validation diagnostic (truncated) as `diagnostic`/`cause`. The file is not rewritten; `.strict()` is unchanged.
- **Restore (operator script, no UI).** `scripts/graph-engineering/graph-record-restore.mjs list|restore`, backed by `adapters/record-maintenance.ts`. Refuses while the application holds the lock; validates the snapshot with the same parser as `read`; saves the current record (even if damaged) into the store first; replaces atomically; touches nothing else.

Spec: [Z8_2_SPEC.md](Z8_2_SPEC.md) (written before the implementation). Operator guide: [GRAPH_DATA_OPERATIONS.md](GRAPH_DATA_OPERATIONS.md).

## 5. The compatibility gap — details and decision

- **What the user sees.** The Graph panel shows a raw JSON dump of the validation error (`Resolved instructions differ from exact frozen iteration bindings.`, path `runs.0`) instead of the runs. No other workspace is affected; the record is unchanged.
- **Confirmed cause.** The frozen `resolvedInstructions` of the reviewer attempts in both fixtures do not contain `Permitted evidence artifact IDs` (checked on the committed bytes); the current `resolveGraphInstructions` appends that contract text for task nodes whose JSON output schema has `evidenceReferences`, and the integrity check in `domain/routing-record.ts` recomputes with current code. `git diff graph-v3.14.0-z7.5 HEAD -- …/domain/bindings.ts` shows the change; `ed3bd3a` is the only commit after the tag that touches it. The routing-record check itself predates z7.5.
- **Why I stopped.** Any fix changes what an integrity check means (for example freezing the contract suffix per record version, or verifying a stored digest instead of recomputing), and AGENTS.md asks to align on design defects first. The Z8.2 task says to fail closed and report. Options for you: (a) version the instruction template and verify older records against the template that wrote them; (b) store/verify a digest of the frozen text; (c) accept that pre-`ed3bd3a` reviewer-loop records are unreadable and make the error readable. I recommend (a) or (b) as a separate, tested change before any internal release, plus a readable error in all cases.
- Other fixtures in the same workspaces would be unreadable too: the whole workspace record fails to load, not only the one run.

## 10. Observations and limitations

1. **Each launch re-snapshots an already-Interrupted record.** Cold load re-commits a record that is already `Interrupted`/`AwaitingContinuation` (new `updatedAt`), so every app start creates a new snapshot of the previous start's output. With the bound of 20, **after about 20 launches the snapshot of the genuine pre-upgrade bytes would be pruned.** I did not change reconcile behavior; a small, testable change (do not recommit/snapshot a record that needs no status change) would remove this. Recommended before relying on the snapshot as the long-term original.
2. The workflow-library file has its own version field; the newer-version error covers workspace records only. A newer library file keeps its generic parse error.
3. The UI shows the raw schema error for any non-newer-version load failure (including the gap above).
4. The `ownership lock` directory (`*.json.lock/owner-…json`) exists while a Host is alive and is not data; tests and the matrix ignore it.
5. Fixtures contain the local temporary paths of the capture machine (`C:\Users\USER\AppData\Local\Temp\zcode-graph-acceptance-*`); they are synthetic and kept as written.
6. Not covered: signed/installed upgrade (Z8.4), credentials/native session migration (deliberately separate), security review (Z8.3).
