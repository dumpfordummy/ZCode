## 2. Guest isolation

Windows Sandbox only (no VM is verifiable without elevation). Config `z8-4-i1.wsb` (generated by `scripts/graph-engineering/i1/i1-stage-host.ps1`): networking, clipboard, audio, video, printer and vGPU disabled; `input` mapped read-only; one initially empty `evidence-export` mapped writable; nothing else mapped. Inputs are copied to guest-local `C:\i1` before use.

`i1-guest.ps1` re-runs an isolation check before every step and refuses (exit 90) unless **all** hold: user is `WDAGUtilityAccount`; no host user profile under `C:\Users`; the input mapping is read-only; no default route; no external reachability; no pre-existing Graph profile at preflight. _(Observed: the guest's `C:\Users` also holds the container's own `ContainerAdministrator`/`ContainerUser` profiles; they are allowed, any other profile name still fails the gate.)_ This refused correctly when exercised on the host with a throwaway work directory (no install, no registry or profile writes). The guest uses its normal Graph profile; `userData` is never redirected.

Loopback provider/recorder runs inside the guest. A guest with externally disconnected networking proves nothing about the app's own network policy.

## 3. Install scope and contract (from source and pinned `app-builder-lib` 26.8.1)

- Assisted NSIS (`oneClick: false`), directory change allowed; **per-user** install is the case under test. All-users/UAC is not covered.
- Install directory (default per-user): `%LOCALAPPDATA%\Programs\ZCode Graph`. Uninstall registration is under `HKCU\...\Uninstall\<key>`; the key is derived by the builder, so it is read from the real package rather than assumed to equal the appId `dev.dumpfordummy.zcode.graph`. _(Observed: key `0b2a5115-bf78-50ff-bc0c-5ade87080831`, `DisplayName` `ZCode Graph <version>` — the version is part of the name, so match the prefix — and `InstallLocation` is empty; the install directory is derived from the uninstall string.)_ Ordinary ZCode uses `dev.zcode.app` / `ZCode`; Preview uses `dev.zcode.app.preview`.
- Update (`isUpdated`): only files listed in the previous `.zcode-install-manifest` are deleted; a missing manifest preserves everything (`cleanup-skipped reason=manifest-missing`). The z8.2 installer's own uninstaller is the one that runs during upgrade, so whether it honors the manifest is observed, not assumed.
- Ordinary uninstall: `RMDir /r $INSTDIR` — **unrelated files inside the install directory are removed**.
- Data retention (expected before testing): the pinned uninstaller deletes `%APPDATA%\ZCode Graph` only when `--delete-app-data` is passed or `deleteAppDataOnUninstall` is configured; neither applies (not configured, flag not passed, no UI option). Graph's private profile `%USERPROFILE%\.zcode-graph-engineering\` is outside AppData and untouched by the uninstaller. **Expected: default uninstall retains all profile data; upgrade retains all profile data.** No deletion option is selected.

## 5. Driving the installed app

_(Observed.)_ There is no `wsb.exe`, so the guest runs an unattended driver from its logon command and exports path-sanitized evidence through the writable mapping. The installed exe is driven with the existing W1 seam, Playwright `electron.launch` (the shipped fuses leave `--inspect`/`--remote-debugging-port` on), in a guest-only `Z1_INSTALLED_PROFILE=1` mode that keeps the guest's real default profile; the installer and uninstaller wizards are driven through UI Automation, recording every page and choice. Node, Git (the Graph runtime shells out to `git`) and the harness are staged read-only next to the installers (`TOOLS-MANIFEST.json`). Only what cannot be automated stays an operator checklist (report §10).
