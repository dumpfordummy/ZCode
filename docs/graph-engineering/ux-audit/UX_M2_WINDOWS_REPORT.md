## 5. Confirmed defect and fix

**1. `pnpm typecheck` fails on Windows (and would on default macOS) at the UX-M2 merge commit.** Found by the first emitting check. UX-M2.2 added two modules in one directory whose names differ only in case and extension: `graphRecipeChanges.ts` (pure comparison) and `GraphRecipeChanges.tsx` (component and hook). TypeScript maps `./GraphRecipeChanges.js` to `.ts` before `.tsx`; on a case-insensitive file system `GraphRecipeChanges.ts` **is** `graphRecipeChanges.ts`, so the import reached the wrong module: 8 errors (TS2724, TS2305, TS1149) in `GraphProjectRecipes.tsx`, `GraphSetupPanel.tsx` and `GraphTemplateBindings.tsx`. Linux could not see it. Preserved evidence: [defect-1-typecheck-before-fix.txt](evidence/ux-m2-windows/defect-1-typecheck-before-fix.txt) (exit 2).

- Specification first: [UX_M2_SPEC.md](UX_M2_SPEC.md) section 6, committed with the fix.
- Fix: the component module is renamed `GraphRecipeChangeSummary.tsx`; three import specifiers changed; exports, markup and test ids are untouched.
- Regression: `packages/ui/test/moduleNameCollision.test.ts` fails on any sibling modules that differ only by case. It failed on the pre-fix tree (on this Windows machine, naming exactly that pair) and passes now. It is a plain file walk, so it also fails on Linux.
- After the fix: `pnpm typecheck` exit 0, lint, architecture, UI tests, then the fresh builds and every native path in section 3.

No other product defect was found. **Stopped-before list:** nothing touched Graph Host ownership or admission, the permission policy, reviewer or evidence semantics, approval, recovery or concurrency.

## 6. Harness findings (not product defects)

1. **Stale UX-M1 native assertion (`ux-m1-native.mjs --journey=checks`, C3).** It compares the whole row text of the selected checks before and after an unsaved edit. UX-M2.2 legitimately adds "Unsaved edits in Checks are not used" to that row, so the comparison failed (log kept). The row helper now strips exactly the two UX-M2 marker phrases before comparing; the saved name, kind and state are still compared, and the markers are asserted by the UX-M2 journeys. The Cloud report had listed only E3/E4 and `occupied` as changed drivers; this one was missed.
2. **The real dialog needs `%USERPROFILE%\Desktop` in an isolated profile.** The isolation sets a private `USERPROFILE`; the Windows dialog opens on its Desktop and, when that folder does not exist, first shows "Location is not available". The UX-M2 launcher and journeys create empty `Desktop`, `Documents` and `Downloads` folders. **The UX-M1 manual launcher does not**, so the UX-M1 manual file-chooser step would have shown that message first (this is what the user may have seen).
3. **Driver construction.** Playwright reports the launcher process; the Electron main process is its descendant, so the driver matches the whole process tree and never touches another application's dialog (the user's own ZCode was not involved). The dialog's controls are classic Win32 windows without UI Automation patterns, so the driver uses window handles with `WM_SETTEXT` / `BM_CLICK`, and reads the File name box with `WM_GETTEXT` (another process's edit box is not readable with `GetWindowText`).
4. `z6-provider-fixture.mjs` now `await`s its responder so the history journey can hold one model reply; synchronous responders behave as before (the reviewer, z6 and script tests all pass).
