1. **A library revision conflict gives no feedback where the user is looking.** Saving from Advanced -> Manual JSON (or any long Share task) at 1280x720: after the refused save the viewport is unchanged (screenshot `s-library-conflict-at-save`), because the error and **Refresh library** sit at the very top of the dialog (screenshot `s-library-conflict-error`); measured: the error is outside the viewport while the pressed button is inside it. A stale "Saved: Share flow · Version 1 is now selected." from the previous success also stays directly under the new error. The spec's "Refresh beside the error" is met; the error's position relative to the action is not addressed by the spec. Proposal: an inline message at the save button, clear the success line when an error is shown (a separate decision).
2. **A Graph record rejected by validation makes the whole Graph panel unusable, with the raw schema error and a Refresh button only.** Seen with the incoherent historical fixture (section 4.3). Pre-existing behavior, relevant only for a damaged record.
3. In Simplified Chinese the Import preview's review line ("Review all portable instructions before importing/exporting. No configuration was installed or executed.") and "Unresolved bindings: Parameter: request, ..." stay English (service-produced text). Workflow names and descriptions are stored content.
4. The Workflows title strip keeps showing "Edited on the canvas / Unsaved changes" after the design was replaced in my journeys (my unsaved probe edit); not investigated.
5. `<html lang>` stays `en` in Chinese (known, out of scope).
