## 5. Confirmed defect and fix

**1. A failed check save was shown beside Review and run after Back to new run.** Found by native step C4 on the pre-fix Desktop build. After a real digest conflict in the Checks editor, **Back to new run** rendered "Project recipe configuration changed; reload before saving." in the New-run action bar, as if Review had failed. It was reproduced first in the browser suite (29 passed, 1 failed, log preserved), then fixed:

- Specification first: [UX_M1_SPEC.md](UX_M1_SPEC.md) section 9.
- Fix: `useGraphEngineering` tags the action error with its source (`errorSource: "checks"` for `saveRecipes`); `GraphRunsDestination` passes the error to the New-run bar and the inline review only when it is not a checks error. The Checks editor still shows it. No new store, single action error kept.
- Regression: the existing browser scenario "cancel, a failed save and a digest conflict ..." now asserts that no `graph-new-run-error` is shown after Back. It fails before the fix and passes after it (30/30). The native step C4 asserts the same on the rebuilt Desktop.
- Pre-fix evidence preserved unchanged: [evidence/defect-preserved/](evidence/defect-preserved/) (native receipt and screenshot, failing browser log).
- After the fix I re-ran typecheck, lint, architecture, the UI tests, rebuilt Desktop, and re-ran every native path in section 3.

Harness issues found and fixed on my side (not product defects): my first typed Enter keystrokes altered the draft text (Enter in a textarea is a newline, restored); the controlled provider only accepts prompts that contain its fixed request sentence; some helpers assumed the English "Allow" label; workspace switching in the app needs the project row's **New task** button; and my three new harness files first exceeded the repository's 400-line lint limit and were split (no exception added).

## 7. Observations (recorded, not fixed, not UX-M1)

1. **`<html lang>` stays `"en"` in Simplified Chinese** (observed in both zh runs). The UI text itself is Chinese. Accessibility relevance only.
2. **A cancelled or unsaved checks edit is retained and written by a later, unrelated explicit Save** (C9 wrote two earlier retained edits). This is the documented and disclosed design (the editor shows "Unsaved project-check edits"), but "Back" is not "Discard".
3. **History is oldest-first and 25 per page**: once history exceeds a page, the newest (often the pending) run is on page 2 while page 1 stays selected. Needs-you and **Go to run** cover discoverability, as designed; a UX-M2 question.
4. **Host error wording is inconsistent in the picker**: the outside-workspace chooser result shows only "Unsafe workspace-relative path segment." while the empty and oversized cases add "Could not use <file>. The previous selection was kept." Host text is shown verbatim by spec.
5. Step names inside captured runs stay English in Chinese ("Final human review", "Test configured criteria"): captured definitions are deliberately not translated.
6. Two one-off environment flakes: the Windows socket buffer page error in a browser suite, and a launch timeout after the harness's theme reload (section 3).
7. The maintained reviewer driver and my journeys cannot answer native permissions in zh-CN (English "Allow" label); the states journey therefore runs in English and reopens the same profile in zh-CN.
