## 3. What was implemented

**UX-M1.1.** While a run waits for a native permission, a native question or the final approval, the New-run form (request, context picker, check choices) stays editable and is kept. A pure `graphAdmission` over the Host run projection separates the _draft lock_ (operation in flight, read-only Host, revision conflict, unavailable, no model) from the _admission lock_ (a run is unresolved). Review and run, Save as workflow only, instantiate, save-replacement and Start are refused on every renderer path: the buttons, their click handlers, `GraphLibrary.onInstantiate` and `apply`, `handleRun`/`startRun`, and the hooks (`run`, `prepareRunConfirmation`, the checks run). The reason and **View current run** sit beside the primary action. A retained lost-ACK submission is reconciled, not blocked. When the run resolves nothing happens: no instantiate, preflight, acknowledgment or Start. The Graph Host remains the authority; these are earlier refusals, never weaker.

**UX-M1.2.** Under each Build/Test step the pane shows the selected checks by stable id (name, kind, "Saved · not run") with **Edit check**. A missing or incompatible id is shown verbatim with the reason and **Open Checks**, blocks Review and is never replaced. **Edit check** opens the one existing Checks editor on that check and moves focus into it; a sticky **Back to new run** bar keeps the way back in view and returns to the untouched draft. The context bar is labelled "For the next run" (its Checks chip stays the project-wide count). **Save checks** is disabled with a reason while a run is unresolved (button, handler and `saveRecipes`); the Host's own rule stays authoritative. A rename keeps the selection; a removal turns it unresolved.

**UX-M1.3.** Focus follows the navigation the user asked for, once (View current run / Go to run to the run summary, New run to the request field, Back to the control that opened the editor) and is never moved by a refresh or Host event. When Review is unavailable for a field, context or check, the sticky bar shows one concise reason and **Go to first field**; a failed instantiate, preflight or Start is shown in the same bar instead of below the fold. Needs-you states its scope (this workspace's runs as reported by this Host, not a queue across workspaces or Hosts). Permission, question, approval, failed Test, invalid evidence, malformed reviewer output and valid reviewer decisions are asserted to be different states in English and Simplified Chinese with raw diagnostics untouched. The unresolved-fields list and the step name `Review` are localized through the existing display map. **Fix:** a preflight reply that arrived after the user left the review used to re-open the abandoned review; an intent token now discards it.

No keyboard shortcut was added. Nothing auto-starts, auto-reviews, auto-acknowledges or queues.

### Boundaries preserved

Graph Host admission (one unresolved run), native permission ownership, preflight acknowledgment (per run, starts unticked), immutable captured runs, strict reviewer validation and recovery are untouched. No permission-policy change, no credentials, no live-model call, no company-project operation, no Z8. User text, instructions, ids, check names, commands, paths, Host diagnostics, evidence and captured definitions are never translated.

## 6. Defects found and fixed during the milestone

1. **A vacuous test of mine.** The first DOM-bypass test passed with every UI guard removed, because React ignores clicks on disabled buttons by props. It now invokes the element's `onClick` directly; the removal is then detected.
2. **A late preflight reply re-opened an abandoned review** (reproduced before the fix, detected by mutation after).
3. **Focus was lost** when View current run, Go to run, New run or Back unmounted the focused control (reproduced before the fix).
4. **A preflight error appeared below the fold** while the primary action stayed in view (reproduced before the fix).
5. **Sticky bars let scrolled content peek out beside them** (found in screenshots; sticky offsets exclude scroller padding). Fixed for the review bar, the New-run bar and the Back bar.
6. **Chinese gaps**: the unresolved-fields list printed raw English labels, and the `review` step had no display name.
7. **Save checks looked usable while the Host would refuse it** with a raw error.
8. **Harness fidelity**: the panel is now viewport-height as in the app, and screenshots are captured without colour transitions (one earlier light-theme image was photographed mid-fade and was discarded).

## 8. Known gaps and recorded out-of-scope findings

- **Windows and Electron are untested.** Focus behaviour after programmatic focus, sticky bars under Windows DPI scaling, native window sizes and real native permission/approval waits are only shown in Linux Chromium.
- **Fixture, not native, run states.** The distinguishable-states evidence uses captured-run variants from the UI unit fixtures; whether real native runs project into the same states is what the Windows checklist item 4 and the six reviewer scenarios are for.
- `useGraphWorkflow.instantiate` has no hook-level admission refusal; instantiate is refused by three UI layers (button and handler, `onInstantiate`, `apply`). Instantiate is not run admission, so adding a hook-level guard is a design decision, not done here.
- The lost-ACK exemption is covered by a unit test only (its timing is racy in a browser). The Design-tab Review path is covered by the hook guard only (stubbed panel body).
- The late saved-checks test proves cross-workspace isolation. The sequence guard for older-versus-newer reads in one workspace is covered by the existing `graphRecipeRead` unit tests.
- The draft is renderer memory (not persisted across an app restart). Custom templates' labels stay as authored in Chinese. Focus is not moved when a history row is selected (the row keeps it). Needs-you is not paged.
- Pre-existing and unchanged: `pnpm lint` warnings (75), repo-wide `fmt:check` findings, a Completed run with no approval-gate record projects as "Unknown".
