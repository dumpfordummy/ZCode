# ZCode Graph 3.14.3-z8.1 — local release candidate (Windows x64) — NOT PUBLISHED

**Status: Z8.1 local candidate, built and inspected. Upgrade, security and install acceptance are pending.** This text is prepared for a possible future publication; nothing was tagged, signed, published or installed. It is not an internal-release approval. An unsigned prerelease: not Latest, not stable, not production-ready.

## What this candidate is

The sequential Graph Engineering product of the accepted UX integration baseline (`51f6ed67`), packaged by the Graph-specific Windows builder, with these Z8.1 changes:

- **Identity.** Application version `3.14.3-z8.1`; the root version is `3.14.3`. The source tree matches upstream ZCode `v3.14.3` for the upstream-changed paths (a path-level comparison, recorded with its exact scope in the release manifest; it is not a claim of whole-tree equality or of upstream ancestry).
- **Parallel (Fork/Join) workflows are disabled in this package.** They stay out of the supported set: their export/import (Z7-A12) and packaged acceptance are incomplete. The Host refuses new parallel plans, previews, preparations and approvals; the interface explains this. Existing parallel history stays readable, and can still be inspected, cancelled or cleaned up. Ordinary Chat and native subagents are unaffected.
- **Automatic telemetry is disabled** for the Graph app, including when telemetry endpoint or OpenTelemetry variables are present in the environment it is started from. This does not claim the absence of all network traffic: model-provider requests you configure, and other native features, behave as they do in ZCode.
- **Release manifest.** Each build produces `RELEASE_MANIFEST.json` (build identity, hashes, toolchain, policies, validation results) and `package-inspection.json` (package content findings). The installer's hash lives only in the external manifest.

## Supported in this candidate

Windows x64, local workspaces, ordinary Chat, sequential Graph workflows with native Build/Test checks, the reviewer, final human approval, the workflow library with versions, sequential import/export, historical run pins, and conservative restart/recovery (interrupted or unknown work is never replayed, approved, answered or released automatically).

**Enabled is not the same as verified.** The manifest records, per capability, whether it is enabled, what development evidence exists, and which packaged-run cases passed. See the Z8.1 report for the table.

## Not supported / not verified

Parallel workflows (disabled); remote, mobile, scheduled or background Graph; MCP, plugins and hooks inside Graph beyond what native sessions already do; live paid-provider runs; code signing; other platforms.

## Carried forward from the unreleased z7.6 notes (reviewer contract and limits)

These statements describe behavior that is part of the source tree. They are reproduced from the unpublished z7.6 notes as accepted by their authors on their builds; they are **not** Z8.1 verification results.

- The built-in generic Sequential Engineering template is **version 2**; new instantiation pins it explicitly. Historical saved definitions and runs are preserved unchanged, and an old built-in-version pin fails explicitly instead of silently changing meaning.
- The reviewer receives the original request and the current Test verification; only the explicitly bound verification artifact may be referenced as evidence. Its output must be exactly one schema-valid JSON object; prose or fenced output is rejected as invalid output.
- A valid `needs_changes` or `needs_human` review is a valid outcome that reaches the final human gate. Invalid output fails the reviewer attempt and routes the run to NeedsHuman without that gate.
- A genuine failed Test stops the generic template before reviewer dispatch; it cannot become a passing reviewed workflow.
- Declared untracked or ignored local source is acceptable evidence when the selected check declares it; Git tracking is not a universal acceptance criterion.
- Reviewer "do not run commands" wording is prompt guidance, not an enforced tool boundary. Build/Test continue to use the existing native manual permission prompts; run-scoped pre-authorization is not implemented.
- The z7.6 notes also report a user-operated live-model manual pilot as PASS. That is the user's own report on a different build; it is not repeated or relied on here.

## Known limitations

- Unsigned; Windows may show an unknown-publisher warning. No signing reputation.
- Fork/Join export/import is unsupported (Z7-A12); do not use a sequential export as a backup of a parallel plan. Parallel is disabled in this package.
- The default credential storage derives its key from the platform, home path and user name; it is not OS-protected storage. Do not describe it that way. A decision is pending for a later Z8 stage.
- There are no Graph retention or deletion controls and no support-bundle generator yet. A backup of Graph data is not a backup of native sessions or credentials.
- No upgrade, uninstall, second-PC or clean-VM testing has been done for this candidate.

## NOT RUN for this candidate

See the Z8.1 report for the exact list. In particular: installing the NSIS installer anywhere, upgrade over an earlier Graph profile, production-environment network-egress measurement, the native Feedback uploader review, signing, Z3–Z7 and UX acceptance in a packaged build, live-provider runs, and mobile/remote/non-Windows.

## Installation (for a future published build)

Download the `.exe` and `SHA256SUMS.txt`, compare the hash, run the installer. GitHub normalizes the space in `ZCode Graph-3.14.3-z8.1-win-x64.exe` to a dot in the download name; the hash applies to the file bytes. The app keeps its private profile at `%USERPROFILE%\.zcode-graph-engineering` and does not copy any ZCode/Codex profile, register the upstream URL handler, or install upstream updates; update by running a newer Graph installer.
