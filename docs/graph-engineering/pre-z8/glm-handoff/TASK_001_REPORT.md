### Cancellation-proof identity correlation — BLOCKED

`assertU4Cancellation` (`pre-z8-u4-proof.mjs:36`) fails with `0 !== 1`. The assertion is:

```js
const matching = inputs.filter((input) => input.id === item.inputId);
assert.equal(matching.length, 1);
```

For the Implement attempt this evaluates `queue_7cccd9b3-675c-4ee0-bed2-0e02544db5e5 === 7cccd9b3-675c-4ee0-bed2-0e02544db5e5`, which is false.

Root cause (read-only diagnosis, no product change):

- The native runtime's `CommandInbox` forms the ledger `id` deterministically as `` `queue_${commandId}` `` — `apps/zcode-cli/packages/bootstrap/src/zcode-protocol-v4/command-inbox.ts:76`, mirrored at `executor.ts:84` (`queueItemId`) and documented at `packages/contracts/src/interfaces/session-store.port.ts:1192` ("由 `queue_<sourceCommandId>` 找回真实 session").
- The Graph run plan assigns `inputId: commandId` (bare UUID) — `packages/services/src/graph-engineering/app/run-plan.ts:58` (and `:200`), `app/routing-plan.ts:41`.
- The native ledger row for the Implement input carries `id = queue_7cccd9b3-...`, `session_id = sess_e1738056-...` (matches the attempt `sessionId`), and `payload.intent.sourceCommandId = 7cccd9b3-...` (matches the attempt `commandId`).

So the correlation is **sound** via `session_id` and `sourceCommandId` (both verified matching), and the `queue_` prefix is deterministic and reversible (`ledger.id === "queue_" + attempt.inputId`). The product was never designed to make the native ledger `id` string-equal the Graph `inputId`; they are two identity spaces.

This is an ownership-contract correlation ambiguity, not a navigation or cancellation defect. Whether it is (a) a product ownership-contract defect — Graph should store the native `queue_` id as `inputId` so records self-correlate without prefix arithmetic, or (b) a proof correlation gap — `assertU4Cancellation` should correlate via `sourceCommandId` (already uniquely identifying) or strip the `queue_` prefix — is a **spec decision** outside TASK_001's harness-only scope. Per the task stop condition ("New failure implies product cancellation, ownership, evidence, historical mutation or recovery defect: keep its evidence; do read-only diagnosis, but do not repair product code under this harness-only task"), the evidence is retained and the product/proof is not modified.

Proposed next scoped task/spec decision: ratify the `inputId` identity contract in `U4_RUN_SPEC.md` / `pre-z8-u4-native-spec.md`. If `inputId` means "the native admission id the ledger uses," fix `run-plan.ts`/`routing-plan.ts` to capture `queue_<commandId>`. If `inputId` means "the Graph command id," adjust `assertU4Cancellation` line 35 to correlate via `payload.intent.sourceCommandId === item.commandId` (and keep the `session_id` check). Either unblocks re-running `--scenario=cancel`; the navigation boundary needs no further work.
