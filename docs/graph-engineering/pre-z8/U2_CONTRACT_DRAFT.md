# U2 contract decisions for the next checkpoint

Status: ratified implementation contract after the verified U1 checkpoint. Implementation is in progress; no U2 completion is claimed. Read `IMPLEMENTATION_SPEC.md` and the .NET audit. Public field names live in `project-setup-types.ts`, `dotnet-types.ts`, `artifact-types.ts`, `tool-types.ts` and `workflow-contract.ts`.

Current primary documentation was checked on 27 September 2026. Microsoft documents that VSTest `--no-build` also disables restore, and that a fixed TRX filename can overwrite earlier target-framework reports. This supports explicit project/framework invocations with owned directories, rather than claiming a fixed-name aggregate is complete: [dotnet test with VSTest](https://learn.microsoft.com/en-us/dotnet/core/tools/dotnet-test-vstest). MTP has a separate command/runner contract and is not enabled by this integration: [dotnet test with MTP](https://learn.microsoft.com/en-us/dotnet/core/tools/dotnet-test-mtp). The actual support evidence remains the pinned SDK 8.0.425 fixture, not a claim that every currently documented SDK/adapter is tested.

## Existing owner, additive capabilities

- Keep `IGraphEngineeringService` bounded. Discovery/static compilation/availability can extend the existing `IGraphWorkflowService` facade through a discriminated project-setup operation; async filesystem and existing-only native metadata remain injected ports. No UI filesystem traversal or cold native skill/runtime startup.
- Real calibration extends the existing Graph `run` command with an explicit checks intent. The same serialized owner performs revision/configuration checks, duplicate detection, parallel/unresolved guard, persist-before-dispatch and native sequencing. Compile a transient tool-only definition into the immutable run; do not save over the user's design. Persist optional purpose metadata and validate it in record schemas. Unknown execution is never retried.
- One read-job owner per workspace/request controls bounded scan cancellation. Late UI responses are generation-checked. Job control is ephemeral read state, not accepted execution or configuration truth.

## Definition-local check requirements

Add an optional Tool-node verification declaration: Build, or Test with an explicit Build node ID. Resolve it into a cloned effective recipe at instantiation/preflight/run-plan construction. This is the only effective-recipe path; never change a globally saved recipe's Build reference. Preserve old definitions' recipe fallback and the legacy built-in slot interpretation established in U1. Validate verifier kind, reference existence, earlier position and dominance on all initial/repair routes.

Multi-project/framework policy: one explicit project/framework per Test invocation and one unique report per operation. A check setup may create several Test recipes and calibration may select them explicitly. The common verified-template form must be able to bind multiple compatible tests without losing any selected test: use a bounded additive local recipe-group binding that expands the canonical graph with stable extra Tool nodes and corresponding reviewer/gate evidence. Existing template v1 content and old instance bindings remain unchanged. Portable capture exposes the expanded graph as individual slots and strips local recipe IDs. Reject excessive resulting graph size; never silently drop selected tests. Conditions/repair declarations must include every expanded Test dependency where supported; otherwise explain a specific unsupported template expansion before mutation.

## Genuine report contract

Add `dotnet-vstest-trx-v1` alongside unchanged `zcode-json-v1`; retain internal normalized `zcode-test-v1` semantics. Descriptor includes explicit project, configuration, framework, optional runtime/filter, expected test assembly and existing count/required-test policy. Command and descriptor must agree; Test may not rebuild/restore. Include every selected scope in recipe/preflight identity.

Use a declared workspace-relative report template with the Host operation ID and validate the resolved path before dispatch. Freeze that resolved path in the Tool attempt; reject pre-existing destination. Native VSTest owns report generation. Verify file/report times against the real operation, source unchanged since Build/Test, exact captured Build output fingerprints and terminal native process outcome before attaching internal identity.

The genuine feasibility fixture establishes that ordinary TRX includes absolute user/assembly paths and the existing privacy redactor changes it. Keep that original preview explicitly redacted/incomplete. Add a single trusted capture operation that reads a bounded, link-safe original snapshot once and supplies the exact bytes to the parser plus original SHA/length/mtime. Derive the safe raw preview from those same bytes; never parse a redacted preview or equate its digest with the original SHA. The Graph owner writes a versioned immutable normalization receipt only after independent native identity, source/build, declared assembly/scope, freshness and terminal checks. The receipt binds parser version, original SHA/length, raw preview ID/digest, normalized artifact ID/digest, native operation, source/build and scope. Retained normalized assertions use the unchanged artifact store; if their identities/status/messages are redacted/truncated, they remain incomplete and cannot authorize success/repair. Cold recovery may inspect a complete receipt but cannot regenerate missing proof from a preview.

Native console output also contains ordinary private paths. For explicitly supported trusted .NET evidence, the process envelope must be represented independently from its output preview: retain exact terminal status/exit/signal/timestamps/byte counts/truncation plus correlated operation identity in the validation artifact, and retain stdout/stderr separately under the existing redaction rules. This never converts a truncated/crashed/cancelled process into accepted evidence. Native output text is not a pass oracle. Legacy JSON/command handling must retain its current semantics unless separately covered by an explicit migration test.

Pure restricted XML parser: 256 KiB input, bounded depth/elements/attributes, one supported root/default TRX namespace. Reject DTD/entity declarations, external references, unsupported processing instructions, duplicate attributes, malformed tags/UTF-8/entities, unexpected structure, duplicate test/report/execution identity, inconsistent counters and partial reports. Never follow attachments or paths from XML. Decode only XML predefined/numeric entities with Unicode validity checks. The application must not depend on an undeclared transitive XML package. Preserve display names/failure details in original reports; use deterministic bounded qualified identities including project/framework/assembly/test identity so equal names from different scopes cannot collide. No 1,000-result truncation or lowered acceptance counts.

Keep process success, report validity and assertion outcome separate. This supported VSTest profile accepts native exit 0 for passing assertions and fixture-proven exit 1 for genuine complete failing assertions. Other exits (including signed/unsigned Windows crash codes) are unsupported execution outcomes and cannot authorize repair. Native cancel/timeout/signal flags contradict successful process evidence even when status/code say completed/0. Each Build output must be freshly produced inside the recorded native start/completion window; a future modification time is invalid. Crashes/cancel/timeouts/partial passing reports/zero/all-skipped/missing-required/stale or mismatched evidence cannot pass or authorize repair. The legacy JSON verifier retains its existing nonzero-exit contract.

Fixture-specific counter observation: VSTest 17.11.1 reports `notExecuted=0` even when complete result entries contain `NotExecuted`. Accept only this documented narrow discrepancy after total/result count, executed=passed+failed, passed/failed counts, every definition/entry/result identity, and all unsupported/error counters reconcile. Derive skipped count from actual entries. A positive `notExecuted` value must equal skipped entries; all-skipped and zero-result reports remain inadequate. This does not permit arbitrary counter mismatches or partial reports.

## Guided discovery and configuration

Bound scan to supported metadata names, safe source manifests and local project references with explicit exclusions; no script/MSBuild evaluation/restore/model/MCP execution. Return all solution/project candidates, metadata provenance and unresolved/dynamic/external imports. No first-solution auto-selection. Test naming alone is a hint. MTP detection is explicit unsupported, not converted to VSTest. Source coverage must include actual local build inputs and test authority; unknown coverage blocks a verified preset. Preserve the current 32-file fingerprint bound until a separately tested increase is justified by evidence; show that limitation before execution.

Forms project canonical recipes: executable, argv, cwd, timeout, target/framework/filter, source/output scopes and acceptance. Preserve custom fields through one draft, with Advanced-only policy for unrepresentable declarations. Digest-conflicting saves fail without replacing external/unrelated config or local edits. Availability lookup is read-only; SDK/version probing is an explicitly approved native command. Save never executes. Run checks now previews exact command, environment/private home, no-restore assumption and possible restore/network effects, then explicitly starts native calibration. Saving a valid profile does not require all tests to pass.

The current native metadata API reports executable resolution and configuration identity, not SDK version, installed package/feed readiness, private-home policy or network policy. Keep those facts explicitly Unknown unless captured by the relevant native probe/operation. Do not infer them from `dotnet` availability or from this repository's isolated fixture policy. Retain existing environment-variable-name redaction support; do not add arbitrary environment injection or copy credentials as a setup convenience. Calibration needs a dedicated checks preview shape, since the existing workflow provenance contract requires a template and model inventory; do not fabricate those fields for a tool-only check.

## Required evidence before U2 closure

Domain/parser adversarial tests, read-only filesystem cancellation/link/limit tests, effective-recipe/renamed-Build and multi-scope identity tests, old-record round trips, native calibration and genuine passing/failing/zero/skipped/invalid/stale/TRX evidence, source/build mutation negatives, zero-execution scan/save/import checks, screenshots and updated support/guide text. No private harness, live provider or user pilot claim. Root serializes emitting builds and runs the integrated graph/native regressions after combined changes.

## Ratified implementation choices

- `projectSetup` actions are `scan`, `cancel-scan`, `validate`, `dotnet-preset`, `availability` and `prepare-checks`. They are read/compile operations only. Only existing `recipes(save)` persists configuration. Only `run(action: checks)` accepts execution.
- A calibration selection contains ordered saved recipe IDs and an explicit Test-recipe-to-Build-recipe mapping. Its transient v4 Tool-only graph preserves the saved design and revision. A separate `dotnet-probe` selection is exactly the selected executable plus `--version`, with a reviewed relative cwd; it uses the same native Tool owner, permission and durable run path, and writes no project recipe.
- `GraphChecksPreview` freezes effective recipes, source fingerprint, recipe/configuration digest, native environment, effects and unknowns; its digest is recomputed at admission. Unknowns require an explicit acknowledgment. A stored checks purpose binds the admitted preview and accepted time. Calibration does not fabricate a template/model provenance.
- A .NET Build profile opts into the structured process envelope through `verifier.dotnet`; Test uses `format: dotnet-vstest-trx-v1` and explicit `target`. Both retain exact argv checks. The preset emits Rebuild with no restore, one chosen project/framework, and requires an explicit reviewed source/output manifest. It never claims discovery proves arbitrary MSBuild behavior.
- TRX parser accepts `Uint8Array` original bytes and the expected absolute assembly identity/native window. It returns deterministic qualified test identities, counts and report times, not Graph authority. The trusted capture and application owner attach operation/source/build identity and the immutable normalization receipt. All retained artifacts use unchanged privacy filtering.
- Multi-test template bindings use additive `recipeGroups` and local `buildMappings`. Expansion must copy all Test evidence dependencies and stay within current graph/binding limits before save; unsupported graphs fail explicitly.
