# Z5 independent domain/application review

Reviewed current Z5 source against the captured Z5 baseline inventory and the Z5 specification. This pass inspected Host route/repair control, native admission, Tool evidence, approvals, cold recovery, artifact lineage and preservation boundaries. It did not launch applications, emitting builds or live providers.

## Findings resolved in this pass

1. **Final gate before later native work.** End dominance alone admitted a final approval followed by an Agent Task or Tool. `domain/routing-readiness.ts` now rejects native work reachable after the configured final gate. Further pure Conditions or human controls remain possible. `app/routing.test.ts` contains an Agent/Tool regression and a permitted additional-gate case; the regression failed before the fix.
2. **Test dependency only checked against topological order.** A Build on one exclusive branch could precede a merged Test in the topological list while being skipped on another selected route. Shared pure `domain/routing-topology.ts` now supplies the same back-edge removal, Start/repair roots and dominance relation to readiness and run preflight. `app/run-plan.ts` rejects the Test before native session creation unless its Build dominates it from both applicable roots. It also rejects Condition machine references whose configured recipe is not a Test. `app/routing-preflight.test.ts` demonstrates both former missing rejections and now asserts zero native create/send and zero persisted runs. `app/routing-region.test.ts` checks repair-entry bypass too. v2–v4 keep the prior sequential rule.
3. **Intermediate approval poisoned by successor reservation.** v5 approval predecessor validation used all visited nodes, including a successor already reserved/created after the approved gate. `domain/approvals.ts` now slices predecessors before the gate when it is already visited, while preserving the all-historical-native-inactive guard. `app/routing-approval.test.ts` proves an approved intermediate gate admits exactly the fresh intended native session/input and reaches the final gate. Before the fix creation occurred but send was blocked.
4. **Cold reviewer enum coercion.** `domain/routing-verification.ts` now requires an actual string rather than `String(value)`. The existing reviewer test now rejects single-element arrays such as `["needs_changes"]`; that case failed before the fix. This matches strict live validation.

The subsequent focused guard audit reproduced two additional defects; both are now resolved with spec changes and permanent red/green regressions:

- Oversized repair feedback formerly marked the current Condition Invalid after it was added to `visitedNodeIds`, causing the strict history validator to refuse the NeedsHuman stop. `app/routing-decision.ts` now removes only this exact current Condition from its iteration's visited list on invalidation. The permanent `app/routing-feedback.test.ts` combines individually valid sub-100,000-character Test/reviewer inputs into an oversized envelope and verifies persisted NeedsHuman, retained Invalid bindings/values/message, unchanged prior visited history and zero successor/iteration/checkpoint/native effects. It also verifies maxRepair=0 remains Evaluated/BudgetExhausted in route history. Intentional NoProgress and BudgetExhausted return paths remain unchanged.
- Predicate operator validation formerly coerced `op` through `String`, admitting `["eq"]`; numeric evaluation could then fall through to another comparison and select an exit. `domain/routing-predicates.ts` now requires an actual string before enum membership. The permanent `app/routing.test.ts` rejects malformed array/null/number/object operators in direct evaluation, definition validation and readiness.

`guard-regressions-red.log` shows both permanent tests failing before the fix; `guard-regressions-green.log` shows all eight focused tests passing after it. Earlier temporary reproduction logs are retained too. The lead's final coordinated typecheck/build and native reruns are tracked separately.

This is a bounded review, not a claim that source tests substitute for the native acceptance matrix.

## Verified ownership and uncertainty boundaries

- `GraphState` remains the sole workspace-serialized mutable owner. Its commit detaches the cache only after repository write success. Native IDs, admission counters and sending intent are persisted before effects; `dispatching` is a one-use live permission, never recreated by a cold phase.
- `GraphSequencer` and `GraphTools` reuse the existing native Agent/recipe ports. Frozen model/mode/recipe configuration remains attached to exact attempts. Unknown native acceptance removes live advancement permission; a late authoritative fact can reconcile the original attempt but cannot resume a route.
- `GraphToolEvidence` distinguishes provenance-valid failed assertions from acceptance. Repairable failure still requires exact operation/source/build/report identity, observed process exit, complete unredacted command evidence, stable captured file bytes, positive named tests and consistent failed exit. Spawn/timeout/cancel/incomplete/stale evidence does not qualify. Failed Build remains a stop.
- `GraphRoutingDecision` reads exact current-iteration artifact bindings, persists selected values/exit and successor checkpoint, and constructs bounded repair feedback. Its checkpoint verification reopens the original decision iteration's retained bytes and re-evaluates the original machine/reviewer evidence. No first/last historical node fallback selects live data.
- `GraphRoutingChecks` rechecks frozen definition/settings/recipe configuration, declared source fingerprint and deadline around admission. Deadline crossing while the sending write is in flight performs no native send/start and retains an uncertain intent instead of rolling the phase backward.
- Cold `GraphState.load` never dispatches. `routeCheckpoint` permits only the exact still-planned native or Pending control successor with historical inactivity proof; active/unknown creating/sending work does not become a continuation. Human Approval continuation remains separately correlated. Recovery release inspects every historical native attempt and never upgrades absence to Tool process cleanup proof.
- The source fingerprint is an observed file-state assertion, not a filesystem lock. Native process cancellation remains the inherited runtime behavior; source review does not prove arbitrary descendant process cleanup.
